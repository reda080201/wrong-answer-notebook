## 원인과 수정

1. **가져오기 확정 내용 불일치**: serde_json 기본 부동소수점 파싱으로 crop 좌표가 JS의 값과 달라질 수 있다. 최소 Rust 실행에서 `0.11458333333333333 → 0.11458333333333331`을 재현했다. `float_roundtrip`에서는 원래 값이 유지됐다. Cargo feature를 켜고, 항목 저장 전에 초안의 payload/hash를 다시 읽어 검증한다. 엄격한 ID/내용 비교와 기존 해시는 유지한다.
2. **복구 상태와 잠금**: 안내 두 개가 중복되고 Dialog의 고정 grid 행 사이에 끼어 있었다. 복구 카드를 본문 안으로 통합하고 확인/이어서 검토/저장 전 취소를 구분했다. 탐색 탭 변경은 허용하지만 확정 중 자료 편집과 staged 자산 폐기는 차단한다. 취소는 항목 큐 안에서 저장소를 다시 읽어 예정 ID가 하나도 존재하지 않는 pending 작업에만 허용한다. 완료/부분/이미 저장된 기록과 읽기 실패는 보존한다. 이미지 파일은 이 작업에서 삭제하지 않는다.
3. **종료 확인 두 번**: 저장 실패 대화상자의 위험 버튼에서 다시 confirm 콜백을 호출했다. 명시적으로 선택한 버튼에서만 이미 확인된 종료를 전달한다. 다른 호출의 확인 절차는 유지한다. 손실 안내와 세 버튼의 간격·위험/주요 스타일도 정리했다.
4. **수학 표시**: 원문과 주석 좌표를 수정하지 않는 표시 어댑터에서 명확한 단일 나눗셈을 세로 분수로 바꾼다. 연결된 나눗셈/모호한 분모의 곱/TeX text 인수는 그대로 둔다. Area(…)는 넓이(…)로 표시하고 제곱근·유니코드 첨자·함수 인수의 곱을 보완했다. 수식 segment의 편집 미리보기에는 수식 구분자를 명시한다.
5. **수식/조건 중복**: canonical 수식과 호환 본문의 `$$…$$`/`$…$` 대응이 빠져 있었다. 여러 문장 조건을 포함한 완전한 projection도 줄 분리 전에 대조한다. canonical 내부 반복과 호환 본문 전용 문장은 제거하지 않는다. 사용자 ZIP의 20번 표시 segment 6→3, 28~30번 4→3으로 원래 canonical 개수와 일치했다.
6. **복습 화면**: 이전 820px max-width 잔재를 해제하고 읽기 여백·배경·헤더를 정리했다. 1100×750에서 카드 폭1052px, 680×750에서632px이며 전체 가로 넘침0px이다. 긴 한 개의 수식은 내부 가로 스크롤로 읽는다.
7. **메뉴/과목**: 시험지함과 파일/ZIP/JSON을 각각 첫 항목으로 배치했다. 과목의 중복 제목을 없애고 제목/관리와 선택 목록의 스크롤을 분리했다. 마지막 과목으로 이동해도 탐색 상단72px와 과목 제목463.39px가 유지되고 목록만228px 스크롤됐다.
8. **AI 설명**: 제공자/정확한 모델 ID/키 위치/활성화 순서, 실제 환경변수 이름, custom URL, 브라우저 제한, 비용 주체, 연결 테스트의 범위, MCP와 앱 대화의 차이를 설명한다. 키나 외부 API를 사용하지 않았다.
9. **반복 처리 비용**: MathText memo/토큰 메모, 복습 현재 문항 계산, 가져오기 비교/프롬프트 계산을 안정된 입력에 묶었다. 문항 번호의 중복 판정은 반복 filter에서 Map으로 바꿨다. #159의 선택 화면 지연 로딩도 포함한다.

## 실제 확인 (격리된 브라우저)

- 사용자 제공 ZIP: 불러오기 → 작업실 → 초안·이미지 폐기 → 재진입. 잔여 복구 카드 없음.
- 실제 남은 초안의 복사본: 내용 불일치에서 저장을 차단 → 저장 전 취소 확인 1회 → 복구 카드 제거 → 직접 입력/파일 탭 사용 가능.

- ZIP 바로 저장 → 원본22페이지·30문항 → 새로고침 → 시험지1개 유지. 20번 일반/크게 보기/오늘 복습에서 분수·시그마·넓이 표시와 중복 제거 확인.
- 1100×750 라이트/680×750에서 복습 화면과 전체 가로 넘침 확인. 과목의 마지막 항목과 수학 선택 가능.

- 독립 수식 화면(30문항, 부모 상태60회 갱신)의 수동 측정: 변경 전986~1641.2ms, 후294.7~341.1ms. 전체 앱 속도나 Windows 메모리 감소로 일반화하지 않는다. 최초 진단 페이지의 doctype 누락은 수정 후 다시 측정했고 제품 오류로 집계하지 않았다.
