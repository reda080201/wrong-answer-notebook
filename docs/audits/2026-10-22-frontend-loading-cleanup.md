# 초기 로딩과 이미지 상태 정리

기준: `main=3c5e9b9aeccc3ee77ac755e0ab19ed84cca09416`. 기존 Draft #158은 변경하지 않고 별도 브랜치에서 진행했다.

## 변경

- 가져오기, 학습 자료 가져오기, 복습, 설정, 문제 모음 구성, 보충 자료 병합·관리·연결의 8개 화면을 동적 import로 전환했다. 화면을 열기 전에는 해당 UI 모듈을 불러오지 않는다.
- 공통 `deferDialog`는 로딩 안내와 닫기를 제공한다. 모듈 로딩 실패는 해당 창에서 다시 불러올 수 있고, 실제 화면 렌더링 오류는 기존 상위 오류 처리에 전달한다. 성공한 화면은 재렌더링 때 동일한 컴포넌트로 유지된다.
- AppModals의 저장·초안 제어, 입력 폼, 가져오기 작업실, AI 대화 제어는 기존 위치에 유지했다. 창 전체에 새 key를 부여하지 않았다. 수식 렌더러의 초기 로딩 경로와 PDF의 기존 동적 import도 유지했다.
- `VisualPaperImportError`와 결과 타입을 작은 서비스 모듈로 옮겨 오류 클래스 때문에 가져오기 UI 전체가 초기 로딩되지 않도록 했다. 기존 컴포넌트 경로의 재수출을 유지해 클래스 identity와 호출 계약을 보존했다.
- ImageThumb와 AnnotatableImage는 모든 호출자가 이미 파일명 key를 사용한다. 파일이 바뀌면 해당 이미지 상태만 새로 생성되므로 effect 안의 중복 동기 초기화 4줄을 제거했다. 비동기 응답 취소와 필기·문항 상태는 유지했다.

## 캐시 폴더

사용자 작업 폴더에 리터럴 `%SystemDrive%/ProgramData/Microsoft/Windows/Caches`가 존재하며 파일 4개, 989,728바이트다. reparse 경로는 없었다. 생성 원인은 확인하지 못했다.

범위를 확인한 PowerShell 재귀 삭제와 절대 LiteralPath 삭제가 모두 자동 승인 검토에서 `blocked by policy`로 차단됐다. 파일은 삭제하지 않았다. 허용된 대안인 루트 한정 `/%SystemDrive%/`를 .gitignore에 추가했고 현재 사용자 체크아웃에도 공통 Git 로컬 exclude로 적용했다. 다른 untracked 보고서는 보존했다.

## 빌드 비교

같은 기준 코드와 설정으로 `vite build --manifest`를 실행했다. entry와 정적 import를 재귀 추적해 초기 JS 전체를 합산했다. 아래는 실행 시간 개선을 측정한 결과가 아니라 파일 크기 비교다.

| 항목 | 변경 전 | 변경 후 | 감소 |
|---|---:|---:|---:|
| 초기 JS | 1,928,263 B | 1,728,326 B | 199,937 B (10.4%) |
| 초기 JS gzip | 570,129 B | 513,675 B | 56,454 B (9.9%) |
| 전체 lint 경고 | 56 | 54 | 2 |

500KB 초과 경고는 남아 있다. 경고 기준과 ESLint 규칙은 변경하지 않았다. 전체 경고의 일괄 수정과 KaTeX 지연 로딩은 이번 범위에 포함하지 않았다.

## 직접 확인과 제한

별도 origin의 브라우저 격리 저장소에서 프로덕션 빌드를 사용했다.

- 설정/구성/가져오기: 첫 로딩 안내 → 실제 창 표시 확인. 설정 테마 변경과 닫기 확인.
- 수식이 있는 문제지 작성·저장·편집: 시그마와 prime 표시 확인.
- 구성 제목 입력 → 조건/미리보기 이동 → 제목 유지 → 저장 → 목록의 제목·2문항 확인.
- 합성 JSON 가져오기 → 구조화 본문 편집 → 작업실 전달 → 저장 → 변경 본문과 수식 표시 확인.
- 1100×750의 페이지, 680×750의 설정 창 가로 넘침 0px 확인. 브라우저 콘솔 오류 0건.
- TypeScript build와 Vite build, lint, git diff --check 통과. 로컬 자동 테스트와 E2E는 추가하거나 실행하지 않았다. 모듈 다운로드 실패/재시도, 실제 이미지 교체·필기, Windows 네이티브 UI·API 제공자는 직접 실행하지 않았다.

검사는 순차 실행했고 실제 사용자 저장소와 설치판은 변경하지 않았다. 새 PR은 Draft로 유지하며 병합하지 않는다. 최종 head CI는 PR 기록에 별도로 기재한다.
