### U01. 일반 오답 보기의 첫 화면에서 정작 문제를 읽기 어렵다

- 재현: 1100×750 → 20번 자동 오답 → 문항 텍스트.
- 기대: 제목과 최소 도구 아래에서 문제 본문을 바로 읽는다.
- 실제: 바깥 제목, 태그·날짜, 학습 흐름, 문제지 제목, 보기 전환, 안쪽 제목·문항/삽화 통계, 문항 헤더가 누적된다. 바깥 제목 top 약 188px, 같은 안쪽 제목 top 약 548px이며, 본문 첫 줄은 화면 하단 약 670px에서 시작한다. 하단 조작바까지 있어 첫 화면의 읽기 공간이 거의 없다.
- 근거: `EntryDetail.tsx:1657`, `EntryDetail.tsx:1811`의 StudyPaperView 호출과 화면. 집중 보기에서는 정상적으로 넓게 읽을 수 있지만 기본 화면의 중복 정보는 그대로다.
- 영향: 스크롤이나 집중 보기 진입을 먼저 해야 한다. 사용자가 말한 “기능은 있지만 화면이 어색하고 무겁다”에 직접 해당한다.

- 영향: 검토 절차가 확인 가능한 완료 상태로 이어지지 않는다.

기본 UI 폰트는 Pretendard 계열이며 1100px 집중 보기에서 분수·시그마·아래첨자와 “넓이”가 정상 배치되는 것을 확인했다. 사용자 ZIP의 20번에서 과거처럼 분모가 단순 `/`로만 표시되거나 `Area`가 그대로 나오는 문제는 이 경로에서 재현되지 않았다. 모든 수식의 수학적 정확도나 원본 전체와의 일치를 검증한 것은 아니다. 모서리 반경 자체의 심한 깨짐보다 중복 헤더, 너무 작은 선택 항목, 잘린 수식, 본문에 묻힌 주요 버튼이 더 큰 문제였다.

## 성능과 미확정 현상

- 63문항 문제은행 화면에 카드 63개, KaTeX 254개, DOM 요소 10,167개가 생성됐다. 화면 밖 카드도 60개가 렌더링돼 있었다. 목록 가상화·페이지 단위 렌더링을 검토할 구체적인 근거다. 이것만으로 메모리 누수나 지연 원인을 확정하지 않는다.
- 시험 시작·응답·전환·평가에서 조작 도구 응답 시간 초과가 반복됐다. 이후 화면에서는 조작이 반영돼 있었다. 실제 사용자 입력 지연과 도구/연결 지연을 분리한 측정은 없다. 제품 기능 실패로 집계하지 않았다.
- 다음 날 재개 시 점검 서버가 종료돼 복습 lazy 화면이 로드되지 않았다. 서버를 복구한 뒤 화면의 “다시 불러오기”로 정상 진입했다. 앱 결함으로 집계하지 않았다.
- 원본 전체 맞춤 직후 도구 영역·집중 모드 전환에 따라 이미지 크기가 변했다. 하단 가림은 안정된 동일 조건에서 재현하지 못했으므로 확정 결함에 넣지 않았다.
- 무결성 검사에서 기존 격리 데이터의 참조 이미지 10개 누락을 발견했다. 이번 새 ZIP 저장의 유실인지, 이전 점검 자료의 잔재인지 입증할 근거가 없다. 검사 결과는 별도 화면으로 보존했다.

## 남은 확인과 수정 순서

1. 기본 읽기 화면의 중복 정보, 가져오기 안내·검토 완료 흐름을 우선 수정한다.
2. 문항 이동 상태, 학습 후보 창의 고정 조작, AI 자료 검색을 수정한다.
3. 설정·체크 영역·목록 요약을 공통 UI 기준에 맞춘다. 문제은행 성능은 실제 입력 지연 측정 후 제한 렌더링을 적용한다.

Windows의 실제 데이터 저장·백업 복원·실전 제출·AI 제공자 응답, 실제 터치, 사용자 PDF 전체, 장시간 실행은 이번에 확인하지 않았다. 이 항목들을 완료로 표시하지 않는다. 점검용으로 만든 항목·응답은 브라우저 격리 저장소에만 있으며, 설치 앱에는 시험 자료를 추가하지 않았다. 사용자 원본 파일과 기존 자료는 삭제·변경하지 않았다.

화면 증거는 비공개 자료가 포함돼 Git에 추가하지 않았다. 로컬 위치: `build/diagram-pipeline/usability-2026-10-26/`. 파일명만으로 결함이 확정되는 것은 아니며, 위 판정과 함께 읽어야 한다.
