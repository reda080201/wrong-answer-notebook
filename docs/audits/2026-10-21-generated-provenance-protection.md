# 생성 시험 출처 로딩 중 실전 자료 보호

## 원인과 재현

기준 head: `5d497e2f0baea6008ab0791df1b1588476d5ac62`.

App은 시험 세션의 loading/loadError만 공유 차단에 반영했다. 원본 ID가 없는 legacy 생성 시험은 생성 모의고사를 읽어야 출처를 복구할 수 있다. 그 데이터가 아직 없거나 실패하면 보호 집합에 `generated:<id>`만 들어가고 원본 ID는 허용됐다. 데이터 로딩이 끝나도 출처가 없거나 중복이면 같은 문제가 남았다.

실제 보호 함수를 격리 실행해 로딩 전/실패의 원본 허용과 성공 후 차단을 확인했다. 회귀 검사를 추가했을 때 수정 전 6개 실패/8개 통과로 누락·중복·빈 출처의 차단 실패를 재현했다. 실제 외부 제공자에게 자료를 보내는 재현은 수행하지 않았다.

## 변경

- `useSavedRealExamProtection`: 시험 기록과 생성 모의고사의 loading/loadError를 함께 반영한다. 재시도는 즉시 보호를 걸고 실행 잠금을 잡은 뒤 기존 유지보수 구간에서 진행 중 저장을 마치고 두 저장소를 다시 읽는다. 두 읽기가 모두 끝나기 전에는 유지보수 구간을 종료하지 않는다. 실패 시 차단과 재시도 안내를 유지하고, 종료 후 늦은 완료는 상태를 바꾸지 않는다.
- `realExamProtection`: 미제출 생성 시험의 원본 ID를 유일하게 복구하지 못하면 자료 접근을 차단한다. 직접 출처가 있거나 유일한 매핑이 복구되면 해당 출처를 보호한다. 미제출 세션이 남아 있는 동안에는 만료·화면 닫기로 보호를 해제하지 않는다.
- `App`: 공통 훅을 사용하고 기록·출처 재조회/실패 안내를 연결한다. 출처가 불명확할 때도 알려진 미제출 실전 시험은 다시 열어 제출할 수 있다.

출처를 확인하지 못하는 동안 다른 자료도 보수적으로 차단한다. 자료 없는 자유 대화는 계속 허용한다. 공개 저장 형식과 기존 데이터는 변경하지 않았다.

## 회귀 범위와 검사 제한

- 실제 생성 모의고사 훅의 지연/실패/오래된 매핑, 재시도 순서·중복 클릭·실패 후 재시도·종료 후 완료.
- 공통 AI 요청 경계에서 원본 자료 차단과 invoke 미호출. 자료 없는 요청은 허용. API 제공자는 모의 응답만 사용한다.
- 출처 누락·중복 시험·중복 위치·빈 출처, 직접 출처와 제출 후 해제.
- 기존 실전/채점 화면 보호와 직접 구성 보호 회귀.

로컬 기본 forks worker는 테스트 실행 전 시작 타임아웃으로 실패했다. 동일 설정·검사·기대값을 유지한 단일 threads worker에서 관련 검사만 순차 실행했다. 테스트 삭제·skip·timeout 증가는 없다. 전체 로컬 검사와 Windows 네이티브/실제 제공자 확인은 메모리 제한에 따른 기존 보류 범위다. 최종 검사 결과와 동일 head CI는 PR의 후속 기록을 기준으로 한다.

수정 후 관련 5개 파일의 30개 검사 통과(50.27초). `tsc -b --pretty false`, 변경한 TypeScript 5개 파일의 lint(오류·경고 0), `git diff --check` 통과. 실제 브라우저 전체 흐름과 실제 외부 제공자 전송은 이번 후속 수정에서 실행하지 않았다.
