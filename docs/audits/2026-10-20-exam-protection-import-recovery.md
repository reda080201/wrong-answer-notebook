## 1. P1 — 닫힌 실전 시험의 자료 보호

### 원인과 수정

AI 보호 정책이 현재 열린 세션만 보아 시험을 닫으면 보호가 풀렸다. 저장된 모든 `real / in_progress` 세션과 활성 세션을 합친 공통 정책을 추가했다. 시간 만료만으로 보호를 풀지 않으며, 제출한 세션의 범위만 해제한다. 기록 읽기 실패 중에는 자료 확인·공유를 차단하고 자료 없는 대화는 허용한다.

원본 항목, 생성 시험 출처, 유일하게 복구 가능한 legacy 출처와 과거 자동 오답의 출처를 보호 범위에 연결했다. 학습 상세·편집·복습·문제 은행·직접/AI 구성·공유·MCP 전송 경계와 기존 대화 표시가 같은 정책을 사용한다. 다른 연습/과거 채점 결과와 생성 시험 출력으로 해설을 확인하는 경로도 차단한다. 이전 MCP 공유 문맥은 보호 시작 시 해제한다.

### 직접 확인

격리 A 문제지로 실전을 시작하고 1번에 ② 응답 → 시험 닫기 → 원본 상세 대신 보호 안내 → AI 자료 선택에 A 제외, B 유지 → 새로고침 후에도 보호 유지 → 이어서 시험 열기 시 ② 유지 → 제출 후 원본/해설 사용 가능을 확인했다.

복수 세션, 만료 상태, 기록 로드 실패, legacy 출처, 과거 자동 오답, MCP 경계와 과거 채점 화면은 관련 회귀 검사로 확인했다. 실제 제공자 API 또는 Windows MCP 클라이언트로 전송하지 않았다.

## 2. P2 — 파일 선택 취소 완료

### 원인과 수정

브라우저 파일 입력의 `change`만 처리해 취소 시 Promise가 완료되지 않았다. 백업과 이미지 추가가 공통 선택기를 사용하며 `cancel`을 빈 선택으로 완료한다. 성공·취소·열기 예외마다 임시 input과 핸들러를 정리하고 한 번만 완료한다.

### 확인

백업 취소 null, 이미지 취소 빈 목록, 선택 뒤 늦은 cancel, 열기 예외 후 재시도와 취소 후 유지보수 잠금 해제를 회귀 검사로 확인했다. 실제 OS 파일 선택창 취소는 이번 브라우저 조작 도구의 제약으로 직접 확인하지 못했다. 네이티브 파일 선택 경로는 변경하지 않았다.

## 3. P2 — 원본 확인 후 직접 구성 유지

### 원인과 수정

출처 클릭이 구성 마법사를 닫고 원본 화면으로 이동했다. 중첩된 읽기 전용 원본 확인 창으로 전환하여 마법사 상태를 유지한다. 원본이 없거나 번호가 모호하면 안내하고 다른 문항으로 추측 연결하지 않는다.

## 4. P3 — 새 업로드 없는 가져오기 초안 복구

### 원인과 수정

복구 진입점이 새 자료를 먼저 올려 작업실을 연 뒤에만 있었다. 빈 가져오기 화면에 `이전 가져오기 이어서`를 제공한다. 기존 초안과 확정 기록을 그대로 기존 자산 검증·저장 결과 확인 절차로 넘긴다. 새 입력/자산이 있으면 복구 버튼을 숨긴다. 읽기/검증 실패는 입력을 폐기하지 않고 재시도를 제공한다.

### 직접 확인

JSON → 작업실 본문 수정 → 초안 보존하고 닫기 → 빈 가져오기 창의 이어서 버튼 → 수정 본문 복원 → 680×750에서 저장까지 확인했다. 저장소를 다시 읽어 가져온 항목 1개, 초안 null, 기존 항목 2개와 제출 응답 보존을 확인했다. 확정 기록 전달·읽기 실패·중복 클릭·검증 실패는 회귀 검사로 확인했다.
