## 원인과 수정

| 항목 | 원인 | 수정 |
|---|---|---|
| 알림 접근 | Dialog backdrop보다 낮은 알림 스택과 창 밖의 키보드 포커스 | 동일한 portal 컨테이너를 최상위 Dialog 내부 알림 행으로 옮긴다. 창을 닫으면 부모 창 또는 기본 위치로 복귀한다. Snackbar DOM·비동기 작업·오류를 재생성하지 않는다. 표시 순서 숫자만 올리지 않는다. |
| 저장 전 원본 | ImageGallery가 저장소 getImageUrl만 조회 | 명시적 resolver/기존 preview context를 사용한다. ZIP의 File을 우선하고, staged 자료는 해당 session으로 조회한다. 임시 자료가 존재할 때 누락 파일을 동명 저장 파일로 대체하지 않는다. |
| 빈 이미지 | 빈 URL 및 실제 img 오류를 처리하지 않음 | 로딩 안내·오류·재시도를 제공한다. 이전 resolver/재시도 응답은 반영하지 않고 저장 연결을 보존한다. 확대창에서 오류 후 닫으면 사라진 썸네일 대신 갤러리로 포커스를 복귀한다. |
| 원본 혼재 | 정리본 후보와 모든 페이지를 현재 문항 원본에 반복 표시 | 명시적 source page/reference/그림 원본만 표시한다. 번호 별칭 또는 파일 참조가 중복되면 첫 항목으로 연결하지 않는다. 나머지 원본 페이지는 펼칠 때만 갤러리를 구성한다. 정리본은 비교 영역에 유지한다. |
| 도구 밀도 | 정상 비교에도 재시도·세부 경고 목록이 항상 표시 | 재시도는 오류 때만, 세부 검사 목록은 접힌 영역으로 제공한다. 원본 유지·실제 비교 확인·선택 정책은 그대로다. |
| 시험 탐색 | 상속한 글꼴 행 높이로 하단 높이 53px 측정 | 해당 compact 탐색 버튼에 UI 14px/20px와 공통 6px 모서리를 적용한다. 기존 최소 버튼 높이와 52px 검사 기준은 유지한다. |
| E2E 저장 경로 | 접힌 저장 옵션 안의 버튼을 직접 찾음 | ‘다른 저장 방법’을 펼친 뒤 실제 바로 저장→재진입→이미지 선택 보존을 확인한다. 저장 검증을 제거하거나 timeout을 늘리지 않는다. |

## 검증 기록

- 추가한 이미지/알림 회귀에서 기존 코드 실패 4건을 확인했다. 수정 후 첫 관련 19개가 통과했다.
- 확장한 관련 11개 파일 76개 통과. 초기에 새 fixture를 함수로 잘못 호출한 부분과 없는 fireEvent.toggle 호출을 수정했다. 기존 기대값을 완화하지 않았다.
- 전체 lint: 오류 0 / 기존 경고 53. 의존성·lockfile은 바꾸지 않았다.
- TypeScript/Vite build 통과. 새 ZIP fixture의 BlobPart 타입 오류는 ArrayBuffer 출력으로 수정했다. 메인 JS 1771.88kB / gzip527.99kB이며 기존 대형 청크 경고는 남아 있다.
- 최종 이미지 포커스 및 ZIP fixture 변경 후 ImageGallery·Dialog·ImportFromGptModal 3개 파일 52개를 다시 통과했다. 새 ZIP 통합 검사는 검수 버튼 활성화와 실제 검수창을 기다린 뒤 원본 표시를 확인한다.
- CSS 소유권 3개와 `git diff --check` 통과.
- 선택 E2E 13개 통과(8분): A4의 1100×750·1280×720·1536×970·1920×1080 세로/가로 8건, 실제 CLI ZIP의 1100/680px 비교→선택→저장→재진입 2건, 위조 SHA 차단 1건, 1100/680px 모달 내 실행 취소·포커스·레이아웃·저장소 복구 2건이다. 기존 실패 10개를 모두 포함한다.
- 알림 동작 버튼에도 공통 UI 스타일을 적용하고 긴 자료명 줄바꿈과 버튼 폭을 분리했다. 마지막 1100/680px 검사에는 긴 영문 자료명, 버튼 14px·모서리 6px, 알림 가로 넘침 방지 확인을 추가했다.
- 추가 검사에서 개발 서버의 cold bundle 로딩 시간이 합성 삭제 대기 기록의 60초 안에 포함되어 기록이 만료되는 fixture 문제가 나왔다. 앱이 준비된 뒤 같은 60초 기록을 만들고 새로고침하는 재진입 경로로 수정했다. 앱의 만료 정책·테스트 시간 제한은 바꾸지 않는다. 본문 크기 실패도 별도로 추적하며 치수 검사를 유지한다.

### 최종 완료 기록

- 긴 자료명·버튼 스타일을 포함한 1100/680px E2E 2개 재통과(1.6분). 앞선 13개와 중복되므로 합산하지 않는다. 알림 넘침·Tab 포커스·본문과 알림 행의 비겹침·실행 취소의 영속 저장·Escape 닫기를 확인했다.
- 긴 자료명 추가 직후 680px 본문 bounding box가 null인 실패 1건도 있었다. 최종 재진입 경로에서는 재현되지 않았으며, 그 실패 자체의 원인은 확정하지 못했다. geometry 진단과 기존 non-null·비겹침 assertion을 유지하며 CI 및 후속 직접 사용에서 관찰한다.
- 마지막 변경 TS/TSX 17개 lint: 오류 0 / 기존 경고 6. 앞선 전체 lint는 오류 0 / 경고 53이었다.
- 최종 TypeScript/Vite build 통과(25.20초). 메인 JS 1771.92kB / gzip528.00kB, CSS340.32kB / gzip69.64kB. 번들 경고는 남기며 실제 앱 속도 개선율로 해석하지 않는다.
- 검사에 사용한 개발 서버는 자동 종료됐고 1420 포트에 잔여 리스너가 없다. 다른 사용자 프로세스와 이전 임시 build 폴더는 정리하지 않는다.
- 같은 Draft PR에 푸시하고 새 head CI 상태는 PR 본문에 기록한다. 전체 로컬 검증과 직접 UI가 미확인이므로 Merge-ready YES로 판정하지 않는다.

## 확인 한계

- 이번 UI 도구에는 열린 앱·탭이 없고 이전 로컬 URL 관측은 정책상 차단됐다. 다른 브라우저나 native 도구로 우회하지 않는다. 자동 E2E 결과를 수동 사용·설치 앱 조작으로 보고하지 않는다.
- 실제 사용자 ZIP/PDF 전체 대조, Windows 설치판, 실제 터치·IME는 미확인이다. 회귀에는 합성 자료와 격리된 브라우저 저장소를 사용한다.
- 전체 로컬 unit/E2E·Rust·Tauri 재컴파일은 요청한 자원 제한에 따라 보류한다. 변경된 Rust 코드는 없다.
- 메모리·체감 속도 개선율은 측정하지 않았다. 펼치지 않은 전체 페이지 갤러리를 구성하지 않는 동작만 검증한다.
- 기존 번들/훅 경고·entryPaneOverrides 정리는 별도 작업이다. 병합과 설치판 교체는 수행하지 않는다.
