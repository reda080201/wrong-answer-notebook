## 별도 확인한 결함

묶음 파트 칩만 setSelectedId를 직접 호출하던 경로를 selectEntry로 통일. App의 requestNavigation을 통해 제출 중 차단·시험 저장/이동 취소 정책이 적용된다. 공통 탐색 훅의 기존 보호 검사와 파트 콜백 검사를 함께 실행했다.

## 검사와 한계

- 관련 unit 3파일 15건 통과: 목록 배치/필터 초기화/외부 선택 표시, 묶음 칩 제한·콜백, 이미지 실패·재시도·늦은 응답, 기존 탐색 보호.
- TypeScript 검사, 변경 파일 lint, CSS 계약 3건 및 Vite build 통과. 기존 번들 경고 유지.
- 초기 브라우저 실행 1건은 탐색 버튼 대기 90초에서 실패. 오류 로그를 추가한 재확인 1건은 20.1초에 통과. timeout 변경 없음. 최초 실패 원인은 미확정이며 환경 문제로 단정하지 않는다.
- 재확인에서 300개 합성 자료로 30→60 DOM 항목, 더 보기 포커스, 실제 Enter/Space 선택, 다섯 화면 폭 가로 넘침 없음 확인. 680px 다크 캡처를 직접 검토했다. 최종 추가 시나리오(마지막 항목·전체 검색·라이트)는 제출 결과에 별도 기록한다.
- 성능 개선율·FPS·메모리 감소 수치는 측정하지 않았다. 이전 코드의 전체 map과 이후 렌더 수를 구분하며, 초기 DOM 축소를 전체 앱 성능 증명으로 취급하지 않는다.
- 실제 Windows 앱, 실제 터치, 화면 낭독기, 장시간 이미지 메모리, 두 화면 공유 이미지 및 실제 시험 저장 실패 UI 주입은 미확인. 공유 URL 해제 코드는 추가하지 않았다.
- 전체 Frontend/E2E/Python/Rust/Tauri 결과는 최종 head CI로 확인하며 로컬 전체 실행은 반복하지 않는다. 성공 전 Merge-ready NO. Draft 유지, 자동 병합·설치판 교체 없음.

## 최종 보완

마지막 항목 검색 추가 중 검색 선택자의 ASCII 말줄임표가 실제 Unicode 말줄임표와 달라 실패하여 접근성 이름 `자료 검색`으로 수정했다. 이후 검색 해제 시 이전 300개 배치가 복구되는 실제 상태 오류를 발견했다. 범위 키 변경 시 배치를 초기화하고 되돌아오기 회귀를 추가했다. 기대값/timeout 변경으로 숨기지 않았다.

수정 후 목록 unit 11/11 통과. 최종 합성 300개 E2E 통과(56.1초): 30→60→300, 마지막 항목 접근, 전체 검색 결과 1개, 검색 해제 30개 복귀, Enter/Space 선택과 더 보기 포커스, 680/768/1024/1100/1200px 넘침 없음. 최종 라이트 680px 화면 직접 검토. 스크린샷은 작업 공간 test-results/list-680.png 등이며 사용자 데이터가 아닌 합성 자료이다. 680px 축소 사이드바의 기존 ‘더 보기’ 줄바꿈은 잔존 UI 개선 후보로 남긴다. FPS·메모리·입력 지연의 정량 전후 비교는 미실행이다.
